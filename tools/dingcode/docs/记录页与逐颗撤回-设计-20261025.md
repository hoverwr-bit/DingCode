# DingCode 会话记录页 + 单钉重跑/撤回 — 设计方案(只读评审稿)

## Context(为什么做)

DingCode 目前的修复结果分散在 `~/.dingcode/runs/<sid>/round-N/` 的 JSON/patch 文件里,只能在 macOS App 的复核窗口(`showAutofixReview`)里看,Windows 用户看不到;无法查看每颗钉的批注/Claude 说明/diff,也无法只对一颗钉改批注重跑、或只撤回一颗钉的修改。本方案在不重构现有架构、不破坏整轮 revert 的前提下,利用现有本地 bridge 增加一个 localhost 会话记录页(Vue3+TS+frappe-ui,预构建静态资源),并补齐:单钉改批注+重跑、可选逐颗模式(独立快照/独立运行/单独撤回+冲突检测)。记录页每钉展示:批注、状态、Claude 一句话说明、代码 diff;按钮:改批注重跑、撤回这一颗(逐颗模式),保留整轮撤回。

安全约束:所有写操作 POST + token + confirm 字段;只读端点不发 CORS;不越界访问。

## 0. 总体决策

- **API 承载**:业务逻辑(merged_pins / revert_snapshot / autofix 编排)全在 handoff.py,新增 `core/runs_api.py` 承载 `/api/*` 与 `/app/*`;`core/bridge.py` 只加路由分发(runs_api 内部延迟 import handoff,避免顶层循环 import)。
- **端口冲突(macOS:Swift BridgeServer 已占 8763)**:采用"python 承载 API + 桌面端反代"方案。App 启动后用现有 `handoffCommand()`(DingCode.swift:2211)以 Process 启动 `python3 handoff.py bridge --port $DINGCODE_API_PORT`(默认 8764),Swift BridgeServer 把 `/api/*`、`/app/*` 前缀反代到 8764;`/api/desktop/*` 不转发、本地处理。纯 CLI 场景 `dingcode bridge` 独占 8763,同进程 serve 全部能力(`/api/desktop/*` 返回 501)。Windows Program.cs PageBridge 同样加 HttpClient 反代并托管 python bridge。
- **同源与 token**:`classify_origin`(core/bridge.py:96)前置判定:normalize 后 origin 的 host ∈ {127.0.0.1, localhost} 且端口 ∈ {本服务端口, 8763} → 返回新值 `("self", None)`;`_write` 对 self **不发任何 CORS 头**(同源不需要;外域构造 loopback Origin 也读不到响应)。同源 POST 浏览器必带 `Origin: http://127.0.0.1:8763`,放行是必须的最小改动。再加 **Host 头校验** 封 DNS rebinding:`/api/*`、`/app/*` 要求 `Host ∈ {127.0.0.1:<p>, localhost:<p>}`,否则 403。token 获取 = `GET /api/session` → 复用 `BridgeState.register()`,暴露等级与现有 `GET /ping` 完全一致。
- **写操作三要素**:`POST + client/token(过现有 client_ok, bridge.py:129) + confirm 字段 == URL 中目标 id`。不匹配 → 403。
- **进度获取**:SPA 每 1.5s 轮询 `GET /api/runs/<sid>`(status.json 由现有 write_run_status 实时更新),不做 SSE,省一条长连接。

## 1. 每颗钉数据模型 / 文件布局

### runs 目录(新增部分标 +)

```
~/.dingcode/runs/<sid>/
  status.json  note.json  prompt.md  log.txt            # 现有,不动
  round-N/                                              # 现有(整轮与单钉重跑共用编号空间)
    manifest.json  pre/  pre.diff  diff.patch
    before.png  after.png  summary.json                 # 现有,整轮 revert 语义原样
    + post/            # 仅 pin_only 轮:touched 文件的"运行后"字节副本(≤2MB/文件)
    + manifest.json += "files_sha256": {rel: {pre:…, post:…}}   # 仅 pin_only 轮
    + summary.json pins[0] += {"pin_only": true, "pin": "<id>", "rerun": k}
```

**逐颗模式 = 依次对每颗钉跑 `autofix <sid> --round N --pin <id>`,每钉占一个 round-N**。不新增目录类型,`round_numbers()` / `merged_pins()` / `revert_round()` / 桌面端 `pollAutofix()` 全部原样工作。10 颗钉 → round-1..round-10,每轮 summary 带 `pin_only/pin`。

### 记录页 SPA 内部模型(PinView)

```
PinView {
  id, note(批注), status, pin_type, x_px, y_px, page.url, window{owner,title},
  rounds: [ { round, pin_only, rerun, summary_zh, status, files[], diff,
              reverted, stale } ],   // stale = 依赖的更早钉已撤回
  latest: 最后一个未 reverted 的 round
}
```

数据来源:`GET /api/runs/<sid>` = 现有 `result_payload(sid)`(handoff.py:1855,已含 merged_pins)+ 各轮 summary 的 `pin_only/pin/reverted/stale`。

## 2. API 端点列表(实现在 core/runs_api.py)

| 方法 路径 | 入参 | 鉴权 | 说明(复用函数) |
|---|---|---|---|
| GET `/app`、`/app/*` | — | Host 校验 | 静态 SPA(白名单后缀 + Content-Type 表 + nosniff) |
| GET `/api/session` | — | self | `state.register()` → `{client, token}` |
| GET `/api/sessions` | — | self | 列 runs/ 下有 status.json 的 sid + 状态/轮次 |
| GET `/api/runs/{sid}` | — | self | `result_payload(sid)`(现有) |
| GET `/api/runs/{sid}/rounds/{n}` | — | self | summary + manifest 摘要(kind/head/reverted/files_sha256 键集) |
| GET `/api/runs/{sid}/rounds/{n}/files/{name}` | name ∈ {summary.json, diff.patch, manifest.json, pre.diff} | self | 原始文件流,大小上限,name 白名单防穿越 |
| GET `/api/runs/{sid}/note` | — | self | runs note.json 原文 |

| POST `/api/runs/{sid}/revert` | `{client,token,confirm=sid,round?}` | write | `revert_round`(现有,整轮回滚不动) |

## 3. 逐颗模式流程(状态机)

```
开启逐颗模式: dingcode autofix <note> --per-pin
  └─ 对 open pins 依次: 取下一轮号 N = round_numbers()[-1]+1
       → subprocess 调 autofix <sid> --round N --pin <pid>   (复用 autofix_main 全链路:
          resolve_autofix_note → open_pins_note(--pin 过滤, handoff.py:1946 已存在)
          → note_target/lookup_binding → build_autofix_prompt → run_engine
          → outside_changes 越界守卫 → close_round)
       → close_round 追加:由 split_patch(L1637) ∪ parse_pin_summary files 得 touched 集,
          每个 rel 复制运行后字节到 post/<rel>(复用 _copy_rel 守卫),
          manifest.files_sha256[rel] = {pre: sha256(pre_bytes(...)), post: sha256(当前)}
       → 一颗失败不中断后续(失败记入该钉 summary,status 照常)
  └─ 全部结束写 status.json 汇总
单独撤回钉 k(POST /api/runs/<sid>/pins/<pid>/revert,新函数 revert_pin,handoff.py 紧邻 revert_snapshot:1487):
  base    = pre_bytes(dest_k, meta_k, rel)      # 钉k 改前
  post9   = post/ 字节                          # 钉k 改后(独立副本,关键)
  current = 磁盘字节
  1) 快路径: sha(current)==post_sha → 直接写回 base(revert_snapshot 单文件版)
  2) 三方合并: git merge-file -p current post base
     —— 语义:以 post 为共同祖先,把 post→base 的改动(撤销钉k)合到 current。
        后续钉改了同文件不同 hunk → 干净合并;改了重叠 hunk → 冲突 exit>0。
        不用 git apply -R(要求 hunk 上下文精确匹配,后续钉近行一改就全盘失败);
        不自写 diff3(git 已是 snapshot_before 的既有依赖,自写无测试收益)。
     exit 0 → 写回,summary_k.reverted=true,后续轮 summary 加 stale:true(UI 标"基于已撤回修改,建议重跑";后续轮 pre/post 副本不改,仍是真实历史,再次撤回时 diff3 语义仍成立)
     exit >0 → 409 返回冲突 rel 列表,磁盘与元数据零改动,提示"请先重跑钉k或整轮回滚"
  3) post/ 缺失或 files_sha256 缺项(2MB 上限/旧数据)→ 该文件仅允许 current==post 快路径,否则拒绝
```

## 4. 单钉改批注 + 仅重跑

- **改批注**:写**源 note 文件**(路径取 `read_run_status(sid)["note"]`,autofix_main:1977 写入,本地可信),原子写(参考 core/sync.py:50 的 os.replace 模式)+ `.bak` 备份;runs/note.json 不手改(下次 autofix 启动会重写)。
- **重跑**:autofix_main 已支持 `--pin`(handoff.py:1946-1949),rerun 端点只做:校验钉仍 open(open_pins_note 语义)→ 下一 round 号 → `subprocess.Popen` 起 CLI;SPA 轮询 status.json 得进度(与桌面端 pollAutofix 同一数据源)。
- **轮次规则**:`if round_n > 3`(handoff.py:1932)改为 `if round_n > 3 and not pin_only` —— 3 轮上限只约束整轮自动循环;新增**每钉上限**:该钉 pin_only 历史轮数 ≥3 → `max 3 reruns for pin X`。round 编号继续向上,merged_pins 按轮序覆盖,记录页自动显示每钉最新轮。

## 9. 风险

1. **同源 POST 的 Origin 放行是安全面变化** — 缓解:self 判定仅覆盖环回自身端口 + Host 校验 + 不发 ACAO + 写操作三要素 + 专项测试。
2. **git merge-file 依赖 git** — 非 git 仓(copy 型快照)合并路径不可用;启动逐颗模式时探测 git,缺失则禁用该端点(快路径仍可用)。
3. **post/ 副本受 2MB 上限** — 大文件缺 post → 撤回该文件仅允许 current==post 快路径,否则拒绝。
4. **Swift 反代阻塞** — URLSession 同步等待设 5s 超时;静态大文件由反代流式转发,body 上限 8MB 与现有 _read_body 一致。
5. **round 编号跨 pin_only/整轮混用** — 按现有"轮号新者胜"语义,记录页明示每轮来源,风险可接受。
6. **Windows 未装 git / 8764 被占** — 启动失败明确落盘 status,error 提示;端口 env(DINGCODE_API_PORT)可覆盖。

4. `revert` 整轮回滚回归通过(现有测试 + 手工)。
